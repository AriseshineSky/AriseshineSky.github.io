# 03 · 会话与上下文管理

## 会话存档与 CLI

会话自动保存在 `~/.config/pi/agent/sessions/`，按工作目录分文件夹，格式为 JSONL（树结构）。

| 命令 | 用途 |
|------|------|
| `pi -c` | 继续最近一次会话 |
| `pi -r` | 浏览并选择历史会话 |
| `pi --no-session` | 临时模式，不保存（查询类问题用它，别污染历史） |
| `pi --name "my task"` | 启动时命名会话（`/name` 亦可改） |
| `pi --session <path\|id>` | 复用指定会话 |
| `pi --fork <path\|id>` | 从指定会话 fork 出新会话文件 |

> 习惯：**每个独立任务一个命名会话**。搜索时一目了然，也方便 `pi -c` 精准续接。

## 会话是一棵树：/tree

`/tree` 是 pi 会话管理的核心。任一历史节点都可选中、继续、长出分支，全部历史保留在一个文件里。

- 按名字搜索；`Ctrl+←/→` 折叠/展开与跳转分支
- `Ctrl+O` 切换过滤（默认 → 无工具 → 仅用户 → 带标签 → 全部）
- `Ctrl+X` 复制选中消息；`Shift+L` 给条目打标签（书签）；`Shift+T` 切换标签时间戳

**分支摘要**：从一个分支跳到另一个分支时，pi 会询问是否把离开的分支总结下来、注入新分支——换了路线也不丢上下文。

**`/fork` vs `/clone`**
- `/fork`：从某条历史**用户消息**另起新会话文件（比如「当初那个方案 A，重新想想」）
- `/clone`：把当前分支整个复制为新会话，从当前位置继续

## Compaction：上下文压缩

LLM 上下文有限。对话变长后 pi 自动把旧消息总结压缩，保留近期细节。压缩是有损的，但完整历史仍在 JSONL 里，可用 `/tree` 回顾。

- **自动触发**：`contextTokens > contextWindow - reserveTokens`；默认 `reserveTokens` 16384
- **手动**：`/compact [你的指令]`——压缩前可以指定「重点保留什么」
- **保留量**：`keepRecentTokens`（默认 20000）以内的最新消息不压缩
- **按模型调优**：`compaction.modelOverrides` 可对不同模型设不同预算（见 05）

你当前的配置：`compaction.enabled: true, reserveTokens: 16384, keepRecentTokens: 20000`（与官方默认一致，合理）。

## 成本与 token 监控

- Footer：`↑in / ↓out / R缓存读 / W缓存写 / CH命中率 / cost / ctx%`
- `/session`：会话级明细（消息数、token、成本）
- 观察点：`R`/`W` 与 `CH` 反映**prompt 缓存**命中情况——同一会话里模型切换得越少、文件重复读得越少，缓存命中越高、越省钱

## 何时开新会话 vs 继续

| 情况 | 建议 |
|------|------|
| 独立小任务（「这个函数怎么用」） | `pi --no-session` 或新会话，别挂在大项目上 |
| 同一任务的多轮迭代 | 继续同一会话（上下文连续性值钱） |
| 任务换方向 / 重试不同方案 | `/tree` 回退或 `/fork`，别硬续 |
| 上下文快满且任务阶段已结束 | 开新会话，把结论写进文件或笔记 |
